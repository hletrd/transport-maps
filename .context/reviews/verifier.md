## Findings

### Critical

#### VER-1 — `graph/nodes.py` uses numpy without importing it: no node index can be built at HEAD
- Severity: Critical · Confidence: High · Status: **Confirmed** (executed)
- Where: `/Users/hletrd/flash-shared/transport-maps/src/transport_maps/graph/nodes.py:61-62` (dataclass defaults `np.zeros(...)`), `:124` (`np.flatnonzero(split)`); imports at `:21-27` have no `numpy`. ruff reports F821 six times.
- Why it matters: `build_index()` is the first thing `build-all`, `solve` and `index` call (cli.py:139,236,255). It raises `NameError: name 'np' is not defined` at `nodes.py:124` (reproduced with stubbed `land_cells`/`cell_class`/`urban_mask`/`scheduled_airports`). Constructing `NodeIndex(cells, [], pos, {}, {}, ())` with defaults — which 20 tests do — raises the same NameError from the `default_factory` lambda. In the pytest run this accounts for 21 errors + 18 failures.
- Failure scenario: a fresh `uv run transport-maps build-all` on HEAD dies before loading the graph; the "resolution-6 grid" commit (1a4d66b) never ran end-to-end from a clean checkout. The build running in this tree (PIDs 12638-12640, started 18:46, before the commit at 23:44) is not evidence for HEAD.
- Fix: add `import numpy as np` after `import h3` in `nodes.py`; add ruff (or at least `ruff check --select F821`) to the pre-commit/CI path so an undefined name cannot land again.

#### VER-2 — `build_index` passes the station tables positionally into the new `base_cells`/`base_index` slots
- Severity: Critical · Confidence: High · Status: **Confirmed** (executed with numpy injected into the module)
- Where: `/Users/hletrd/flash-shared/transport-maps/src/transport_maps/graph/nodes.py:184-187` vs field order at `:42-65` (`… dropped_airports, stations, base_cells, base_index, fine, _split, _station_pos, _station_cell`).
- Why it matters: after VER-1 is patched, `NodeIndex(cells, codes, cell_pos, airport_pos, airport_cell, tuple(dropped), tuple(station_keys), station_pos, station_cell, base_cells=…, …)` binds `station_pos` → `base_cells` and `station_cell` → `base_index`, then also receives `base_cells=` by keyword: `TypeError: NodeIndex.__init__() got multiple values for argument 'base_cells'`. Even if the keyword were removed, station lookups would silently land in the wrong fields.
- Failure scenario: identical to VER-1 — `build_index()` cannot return. It also means commit 1a4d66b's own claim that the index "keeps the base grid, each cell's base index and a split set" was never executed.
- Fix: construct with keywords (`stations=tuple(station_keys), _station_pos=station_pos, _station_cell=station_cell, base_cells=…`), or move the three `base_*` fields after `_station_cell`. Add a unit test that calls `build_index()` with stubbed sources (the stub used in this review is six lines) so the constructor is exercised without the 4-million-cell land mask.

### High

#### VER-3 — Coverage-gate `SystemExit` inside a forked worker hangs the build instead of aborting it
- Severity: High · Confidence: High · Status: **Confirmed** (behaviour reproduced with the same `fork` context + `Pool.imap`)
- Where: `/Users/hletrd/flash-shared/transport-maps/src/transport_maps/cli.py:83-87` (raises `SystemExit`), `:182-191` (`ctx.Pool(workers)` + `pool.imap`), docstring at `:131-136` ("Aborts on the first failing gate").
- Why it matters: `multiprocessing.pool.worker` only catches `Exception`; `SystemExit` propagates, the worker process exits, the pool respawns a replacement, and the task's result never arrives — `imap` blocks forever. Reproduction: a 2-worker fork pool whose task raised `SystemExit` hung until a 20 s alarm fired. The tests (`test_cli.py:107-125`) only cover the serial path (`_worker_count` returns 1 below 4 origins).
- Failure scenario: any origin below 90 % coverage in a full 553-origin build leaves an idle process tree that looks like a slow build for hours; `index.json` is never written, but nothing says why.
- Fix: raise a normal exception (`RuntimeError`/`ValueError`) from `_solve_one` and convert to `SystemExit` only in `main()`; add a test that runs `_build_all` with ≥ 4 fake origins and a failing coverage value under a timeout.

#### VER-4 — A ferry between a fine cell and its adjacent unsplit base cell duplicates a ground edge and makes `build_graph` refuse the graph
